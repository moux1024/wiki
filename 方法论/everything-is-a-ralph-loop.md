# Everything is a Ralph Loop

> 来源: https://ghuntley.com/loop/
> 日期: 2026-05-11
> 分类: 方法论
> 标签: AI编程, Ralph循环, 编码代理, 软件工厂, 进化式软件, 自动化开发
> 原作者: George Huntley (@ghuntley)

我一直觉得，现在我构建软件的方式和三年前截然不同。不，我说的不是通过使用 AI 来加速开发，而是在更根本的层面——方法论、技术和最佳实践上的转变。

传统的软件实践是像搭积木一样逐层垂直构建——就像 Jenga。但如今，我把一切都当作一个循环（loop）来处理。你看，Ralph 不仅仅是 forward mode（自主构建）或 reverse mode（clean room 逆向工程），它更是一种思维方式——这些计算机确实是可以被编程的。

看这个视频来理解这种思维方式。

我仍然作为工程师存在，就像在积木时代一样，但我现在是在编程循环（programming the loop），自动化我的工作职能，消除雇佣人类的需求。

现在每个人都在经历他们的疯狂期——就像我曾经用 forward mode 在全自动驾驶模式下 AFK 构建软件那样——但我希望大家能从轨道上回来，记住 Ralph 原始帖子中的这段话。

当我在 SFO 时，每个人似乎都在试图攻克 multi-agent、agent-to-agent 通信和多路复用。在这个阶段，这些并不需要。想想微服务及其带来的所有复杂性。现在，想象一下如果微服务（agents）本身是非确定性的——那将是一团糟。微服务的对立面是什么？单体应用。一个垂直扩展的单操作系统进程。Ralph 就是单体的。Ralph 在单个仓库中以单个进程自主工作，每个循环执行一个任务。

软件现在就像陶轮上的粘土——如果有什么不对劲，我只需把它扔回轮子上，去处理需要解决的问题。

Ralph 是一种 orchestrator 模式，你分配一个包含所需支撑规格的数组，然后给它一个目标，再循环这个目标。

重要的是要观察循环，因为那是你个人发展和学习的来源。当你看到一个失败域时——戴上你的工程师帽子，解决问题，确保它不再发生。

在实践中，这意味着通过提示手动进行循环，或者通过自动化进行，但会有一个需要按 CTRL+C 才能进入下一个任务的暂停。这仍然是 ralphing，因为 Ralph 的核心是通过 context 工程（context 工程）最大化底层模型的能力，而这个模式是通用的（GENERIC），可以用于所有任务。

我一直在琢磨一个叫 "The Weaving Loom"（织布机）的东西。Loom 的源代码现在可以在我的 GitHub 上找到。Loom 本质上是进化式软件的基础设施。Gas town 专注于旋转盘子和编排——完整的 level 8。我要追求 level 9，让自主循环进化产品并自动优化以产生收入。进化式软件——也叫软件工厂（software factory）。

现在出现了一个分水岭——我们有软件工程师在公开拒绝 AI，或者仅仅通过 Claude Code/Cursor 来加速积木搭建过程……但软件开发已经死了——我终结了它。软件现在可以以比麦当劳翻汉堡工人的工资更低的成本开发，而且可以在你 AFK 时自主构建。

我现在不会雇佣你，除非你拥有这些基础知识，并能展示你用它构建了什么。

虽然软件开发/编程现在已经死了。但我们深深需要具备这些技能的软件工程师，他们理解 LLM 是一种新型可编程计算机。如果你还没有构建自己的编码 agent——请尽快动手。

任何发现的缺陷都可以通过 forward ralph loops 来解决。在过去一年里，模型变得相当好，直到现在我才能实现这个完整愿景，但我留给亲爱的读者一个问题……如果模型不断变好，永不停歇呢？
